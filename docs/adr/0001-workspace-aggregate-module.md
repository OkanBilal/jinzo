# Consolidate workspace + activity + diffs + reviews + findings into one workspace module

The five tables `workspaces`, `workspace_activity`, `workspace_diffs`, `reviews`, `review_findings` were originally five sibling modules under the project's per-table 6-file layout. They always travel together: every renderer consumer of activity / diffs / reviews / findings is workspace-scoped (no cross-workspace reader exists — `pulse` doesn't touch them and `stats` joins `workspace_diffs` directly via its own repo, not via the satellite module). Four of the five satellites' service files were pure pass-throughs over their repos (the deletion test: removing them concentrated complexity nowhere — it just disappeared).

We consolidated them into a single `workspace/` module with the flat 6-file layout (one `workspace.repo.ts` covering all five tables, one `workspace.service.ts` covering all five concepts' logic, etc.), one `workspace:*` IPC namespace with narrow channels, and one `workspaceApi.ts` on the renderer with split RTK Query tag types so UI sections still refresh independently. Cross-module writers (drivers, run-session, guards, mains-tools) now import a single named `logWorkspaceActivity` function from the module's barrel rather than the full `workspaceActivityService` surface.

The decision is hard to reverse (touches the IPC seam, preload surface, renderer api files, and ~10 test files) and surprising without this context — a future reader sees one folder owning five tables, which violates the otherwise-uniform per-table convention. It's a deliberate exception: the five tables are one aggregate, and the layering symmetry was costing more in navigation than it earned in consistency. Future architecture reviews should not propose re-splitting them.
